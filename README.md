# Lectern

Lectern is a local documentation hub for browsing Markdown documents spread across many projects, such as specs, PRDs, architecture docs and stories generated by BMAD or Claude Code.

It runs a single [MkDocs](https://www.mkdocs.org/) instance with [Material for MkDocs](https://squidfunk.github.io/mkdocs-material/) and pulls each project's docs directory in via symlinks. Projects can be registered once and then switched on and off without any reconfiguration. Nothing is copied, and nothing is ever written into the project directories themselves.

## How it works

```
~/lectern/
├── lectern            # management script
├── mkdocs.yml         # MkDocs + Material configuration
├── projects/          # one symlink per registered project → its docs directory
└── docs/
    ├── index.md       # hub start page; project list is maintained automatically
    └── <name> → ../projects/<name>   # one link per *active* project
```

Lectern uses two levels of symlinks. `projects/` holds every registered project. `docs/` (the MkDocs `docs_dir`) holds links only for the active ones, so enabling or disabling a project just adds or removes a single link.

Whenever the set of active projects changes, the script rewrites the project list in `docs/index.md`. Navigation within each project is generated by Material for MkDocs from the folder structure.

## Requirements

- Linux, macOS, or Windows via WSL, with bash and GNU coreutils (`readlink -f`)
- Python 3.9+
- `mkdocs` and `mkdocs-material`

## Installation

If you already have mkdocs and mkdocs-material installed you can skip this. If not then install them:
```bash
cd ~/lectern
uv sync
```
Then add the bash script to path:
```bash
chmod +x lectern
mkdir -p ~/.local/bin
ln -s ~/lectern/lectern ~/.local/bin/lectern
```

The script prefers `.venv/bin/mkdocs` if it exists and falls back to `mkdocs` on your `PATH` otherwise.

If `~/.local/bin` is not on your `PATH`, add this to `~/.bashrc` or `~/.zshrc`:

```bash
export PATH="$HOME/.local/bin:$PATH"
```

## Configuration

### Server address

The address is determined in this order:

1. The environment variable `LECTERN_ADDR`, e.g. `LECTERN_ADDR=0.0.0.0:8000 lectern start`
2. `dev_addr` in `mkdocs.yml`
3. The default, `127.0.0.1:8000`

### Start page

`docs/index.md` is created automatically if it doesn't exist. The project list is written between these markers:

```markdown
<!-- lectern:start -->
<!-- lectern:end -->
```

Everything outside the markers is left untouched, so you can add your own intro text and move the markers wherever you want the list to appear.

## Usage

| Command | Description |
|---|---|
| `lectern add [name] <path>` | Register a project's docs directory and enable it. Relative paths work. Without a name, the folder name is used, or the parent folder's name if the target is called `docs`. |
| `lectern remove <name>` | Unregister a project |
| `lectern enable <name>` | Show a registered project in the hub |
| `lectern disable <name>` | Hide a project without unregistering it |
| `lectern list` | Show all registered projects with their state (`on`, `off`, `BROKEN`) and target path |
| `lectern start` | Start the server in the background |
| `lectern stop` | Stop the background server |
| `lectern restart` | Restart the background server |
| `lectern status` | Show whether the server is running, and where |
| `lectern logs` | Follow the server log |
| `lectern serve` | Run the server in the foreground (Ctrl+C to stop) |

Example:

```bash
cd ~/code/project-a
lectern add ./docs                    # registered as "project-a"
lectern add specs-b ~/code/project-b/specs
lectern start                         # → http://127.0.0.1:8000
lectern disable specs-b
lectern list
```

The background server is started with `nohup` and survives closing the terminal, but not a logout or reboot. Its PID and log are stored in `.lectern.pid` and `.lectern.log`. If a background instance is running, enabling or disabling a project restarts it automatically.

### Navigating

- `/` or `s` opens search, and `n` / `p` go to the next or previous page.

## Things to know
- **WSL Live Reload**: When using Windows, live reload only works for projects stored in the WSL filesystem. WSL2 receives no file-change events for files on the Windows drive (/mnt/c/...), so changes there only appear after lectern restart.
- **Link the docs directory, not the project root.** Linking a whole repository pulls in `node_modules`, virtual environments and the like, which slows builds and can cause symlink loops.
- **Dot-directories are ignored.** MkDocs skips anything starting with `.`, so content in folders like `.claude` won't appear unless you link it under a non-dot name.
- **Only Markdown is rendered.** YAML and other files are symlinked but not displayed as pages.
- **Links within a project work.** Links that leave the project's docs directory (e.g. `../README.md`) break and show up as warnings in the log.
- **Broken links:** if a project is moved or deleted, `lectern list` shows it as `BROKEN`. Remove it or add it again with the new path.
- **Large hubs:** MkDocs rebuilds the whole site on every change. With many active projects, disable the ones you're not using.
- **Live reload:** Changes in symlinked projects are picked up automatically. If edits in a newly enabled project don't show up, run `lectern restart`.

## Portability

Lectern relies only on plain symlinks, core MkDocs and Material for MkDocs, with no third-party plugins. The setup should therefore carry over to Zensical, the successor to Material for MkDocs, with little or no change.
